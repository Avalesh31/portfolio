# Exercise 08 — Актуализация UC02

## UC02 "Сформировать расписание мастера"

### Назначение
Менеджер создает и корректирует расписание мастера в виде часовых слотов, чтобы клиенты могли выбирать доступное время для записи.

### Участники и приложения
- Роль: `Менеджер`
- Клиентское приложение: `Web UI барбершопа`
- Серверное приложение: `BRSP Core API`
- Внешний сервис: `Notification API / SMS Gateway` в альтернативном сценарии переноса

### Предусловия
- Менеджер аутентифицирован.
- В системе есть справочник сотрудников и ролей.
- В системе есть мастера с ролью `MASTER`.
- Менеджер получил график работы мастеров.

## Основной сценарий

| Шаг | Приложение | Роль | Действие | Интеграционный метод |
| --- | --- | --- | --- | --- |
| 1 | Web UI | Менеджер | Открывает страницу управления слотами мастеров | Нет |
| 2 | Web UI | Менеджер | Выбирает дату, слот и мастера | Нет |
| 3 | BRSP Core API | Система | Проверяет, что сотрудник имеет роль `MASTER` | `GET /api/v1/employees?role=MASTER` |
| 4 | BRSP Core API | Система | Проверяет, что выбранный слот не забронирован клиентом | `GET /api/v1/master-slots/availability` |
| 5 | Web UI | Менеджер | Подтверждает закрепление времени за мастером | Нет |
| 6 | BRSP Core API | Система | Создает или обновляет слот | `PUT /api/v1/master-slots/{slotId}` или `POST /api/v1/master-slots` |
| 7 | Web UI | Система | Показывает подтверждение сохранения расписания | Нет |

## Альтернативный сценарий: слот уже забронирован клиентом

| Шаг | Приложение | Роль | Действие | Интеграционный метод |
| --- | --- | --- | --- | --- |
| A1 | BRSP Core API | Система | На шаге 4 обнаруживает, что слот уже занят | `GET /api/v1/master-slots/availability` |
| A2 | Web UI | Система | Сообщает менеджеру о занятом слоте | Нет |
| A3 | Web UI | Менеджер | Связывается с клиентом и согласует перенос | Нет |
| A4 | BRSP Core API | Система | Вносит изменение в бронь и новое расписание | `PUT /api/v1/master-slots/{slotId}` |
| A5 | Notification API | Система | Отправляет SMS клиенту об изменении времени и/или мастера | `POST /api/v1/notifications/booking-change-sms` |

## Вывод

В UC02 основная интеграционная логика связана с:
- выбором мастера по роли;
- проверкой доступности слота;
- фиксацией слота;
- уведомлением клиента при переносе уже существующей записи.
