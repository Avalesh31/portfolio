## Требования к обработке ошибок на каждом шаге UC04

| Шаг UC04 | Проверки и требования |
| --- | --- |
| 1. Открытие страницы регистрации | Проверить аутентификацию сотрудника и наличие роли `MANAGER`; при отказе вернуть `403` |
| 2. Ввод имени и телефона | Проверить обязательность, тип, длину и формат введенных значений |
| 3. Проверка отсутствия телефона в системе | При недоступности сервиса поиска вернуть техническую ошибку; при конфликте номера вернуть бизнес-ошибку |
| 4. Регистрация клиента | Создание `Persona` и `Customer` должно быть атомарным; при ошибке откатывать транзакцию |
| 4. Генерация временного пароля | Если пароль не сгенерирован, регистрация считается неуспешной |
| 4. Отправка SMS | Ошибки доставки должны фиксироваться отдельно от ошибок регистрации клиента |
| Альтернативный сценарий с существующим номером | Возвращать понятное сообщение и не создавать дублирующую запись клиента |

## Общие требования к обработке ошибок

1. Каждая ошибка должна иметь человекочитаемое сообщение.
2. Каждая ошибка должна иметь машиночитаемый код.
3. В технических ответах должен возвращаться `requestId`.
4. Для ошибок валидации полей желательно возвращать имя поля.
5. Ошибки интеграции с внешней системой должны логироваться отдельно.
6. Ошибки бизнес-валидации и технические ошибки не должны смешиваться под одним кодом.
