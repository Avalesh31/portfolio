# Exercise 02 — Актуализация UC04

## UC04 "Зарегистрировать клиента (менеджер)"

### Назначение
Менеджер регистрирует клиента по телефону, чтобы затем записать его на обслуживание и инициировать отправку регистрационного SMS с временным паролем.

### Участники и приложения
- Роль: `Менеджер`
- Клиентское приложение: `Web UI барбершопа`
- Серверное приложение: `BRSP Core API`
- Внешний сервис: `Notification API / SMS Gateway`

### Предусловия
- Менеджер аутентифицирован в системе барбершопа.
- У менеджера есть роль `MANAGER`.
- Менеджер находится на странице регистрации клиента.
- Менеджер получил от клиента имя и номер телефона.
- Для отправки уведомления в интеграционном сообщении передаются коды справочников `notificationType=REGISTRATION` и `channel=SMS`.

### Постусловия
- В случае успеха в системе создан клиент.
- Для клиента сгенерирован временный пароль.
- Во внешний сервис отправлен запрос на регистрационное SMS.
- Менеджер видит результат регистрации.

## Основной сценарий

| Шаг | Приложение | Роль | Действие | Интеграционный метод |
| --- | --- | --- | --- | --- |
| 1 | Web UI | Менеджер | Открывает страницу регистрации клиента | Нет |
| 2 | Web UI | Менеджер | Вводит имя и номер телефона клиента | Нет |
| 3 | BRSP Core API | Система | Валидирует формат телефона и обязательность полей | Нет |
| 4 | BRSP Core API | Система | Проверяет, существует ли клиент с таким телефоном | `GET /api/v1/customers/by-phone` |
| 5 | BRSP Core API | Система | Подтверждает, что телефон свободен | Нет |
| 6 | BRSP Core API | Система | Создает `Persona` и `Customer`, генерирует временный пароль | `POST /api/v1/customers/manager-registration` |
| 7 | BRSP Core API | Система | Формирует текст регистрационного сообщения | Нет |
| 8 | Notification API | Система | Принимает запрос на отправку SMS | `POST /api/v1/notifications/registration-sms` |
| 9 | BRSP Core API | Система | Фиксирует идентификатор уведомления и статус отправки | Нет |
| 10 | Web UI | Менеджер | Видит сообщение об успешной регистрации клиента | Нет |

## Альтернативные сценарии

### A1. Телефон уже зарегистрирован

| Шаг | Приложение | Роль | Действие |
| --- | --- | --- | --- |
| A1.1 | BRSP Core API | Система | На шаге 4 находит клиента по номеру телефона |
| A1.2 | Web UI | Система | Возвращает менеджеру сообщение, что номер уже зарегистрирован |
| A1.3 | Web UI | Менеджер | Либо вводит другой номер телефона, либо прекращает регистрацию |

### A2. Некорректный номер телефона

| Шаг | Приложение | Роль | Действие |
| --- | --- | --- | --- |
| A2.1 | BRSP Core API | Система | На шаге 3 обнаруживает неверный формат номера |
| A2.2 | Web UI | Система | Показывает ошибку валидации |
| A2.3 | Web UI | Менеджер | Исправляет номер и повторяет отправку |

### A3. SMS-сервис недоступен

| Шаг | Приложение | Роль | Действие |
| --- | --- | --- | --- |
| A3.1 | Notification API | Система | Не отвечает или возвращает техническую ошибку на шаге 8 |
| A3.2 | BRSP Core API | Система | Сохраняет клиента, фиксирует статус уведомления `FAILED/PENDING_RETRY` |
| A3.3 | Web UI | Система | Показывает менеджеру, что клиент зарегистрирован, но SMS не доставлено |
| A3.4 | BRSP Core API | Система | Передает запрос на повторную отправку по регламенту retry |

## Справочники, используемые в UC

| Справочник | Использование в UC | Участвует в интеграции |
| --- | --- | --- |
| `EmployeeRole` | Проверка, что текущий сотрудник является менеджером | Нет |
| `NotificationChannel` | Значение `SMS` в запросе уведомления | Да |
| `NotificationType` | Значение `REGISTRATION` в запросе уведомления | Да |

## Принятое решение по передаче справочников

Выбран вариант `2`: требующаяся запись справочника передается вместе с исходным сообщением.

Почему:
- для UC04 нужен только один конкретный канал уведомления `SMS`;
- не требуется отдельная синхронизация полного справочника для успешного выполнения сценария;
- это уменьшает количество runtime-вызовов.
