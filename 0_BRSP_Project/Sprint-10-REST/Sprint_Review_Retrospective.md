# Обзор спринта и ретроспектива

## 🏆 Достижения спринта
- Сформировано представление о том, какие части интеграций и данных должны быть реализованы через REST‑API
- Определён базовый набор сущностей и операций, которые логично вынести в API
- Заложены основы для дальнейшей спецификации конечных точек и контрактов

## 🔄 Ретроспектива

### Что прошло хорошо 👍
- **Опора на предыдущие спринты** — проектирование REST‑слоя отталкивается от уже проработанных данных и интеграций
- **Фокус на сценариях использования** — обсуждение API шло от потребностей клиентов и внешних систем, а не “от таблиц”
- **Выделение приоритетных операций** — определены ключевые запросы для MVP

### Что можно улучшить 💡
- **Формализация контрактов** — необходима дальнейшая детализация схем запросов/ответов
- **Нефункциональные требования к API** — важно связать REST с НФТ по производительности и безопасности
- **Документирование версионирования и политики изменений** — пока эти вопросы только намечены

### План улучшений 📅
- [ ] Описать базовый набор REST‑эндпоинтов в виде спецификации (например, OpenAPI)
- [ ] Связать каждую операцию API с соответствующими функциональными и нефункциональными требованиями
- [ ] Зафиксировать подход к версионированию и управлению изменениями в API
