 # Спринт 7: Управление требованиями

 **Статус:** ✅ Завершен  
 **Цель спринта:** сформировать системное понимание жизненного цикла требований, научиться управлять изменениями, приоритизацией и трассируемостью требований в продукте.

 ## 🎯 Логика группировки

 *Спринт основан на учебном проекте `BSA13_RequirementsManagements` и обобщает практики управления требованиями, применимые к CRM‑системе сети барбершопов.*

 ## 📊 Состав спринта

 - **BSA13:** Управление требованиями, приоритизация, планирование релизов и работа с изменениями

 ## 🔗 Бизнес-ценность

 Управление требованиями обеспечивает контролируемое развитие продукта: помогает согласовывать изменения с бизнесом, сохранять целостность модели требований и прозрачность для команды разработки. В результате заинтересованные стороны понимают, **что** войдёт в релиз, **когда** и **почему именно это** имеет приоритет.

 ## 🎯 Ключевые результаты

 - **Каталог требований** с типизацией (бизнес‑, пользовательские, системные и др.)
 - **Матрица приоритизации** требований
 - **Планирование релизов по спринтам/неделям**
 - **Трассируемость** требований к стейкхолдерам, процессам и артефактам

> Проект выполнялся в команде с использованием SaaS‑сервиса управления задачами и требованиями **Weeek**.  
> В портфолио вынесены агрегированные таблицы и скриншот доски Weeek, отражающие итоговое состояние требований.
